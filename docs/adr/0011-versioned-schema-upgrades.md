# Version every component and ship upgrade SQL

Each PostgreSQL component records its own schema version in `webhook_schema_version`, keyed by component name. Before schema 4, only delivery recorded a version and management storage was probed by column names, so a management change had no way to be detected or gated. Schema changes now ship as upgrade SQL generated by `getPostgresUpgrade({ from })` and as files under `migrations/upgrades/`, never as fresh-install SQL alone. The upgrade SQL checks the recorded version first and raises inside the host's transaction otherwise.

`check()` on every component requires exactly the version the package was built for. A newer package on old storage and an old package on upgraded storage both refuse to start and name the next step. Release notes state whether processes on the previous package may keep running while the SQL is applied; the rollout order is SQL first, then producers, then workers. CI rehearses each upgrade against the previously published package with a pending backlog.

Accepted on 12 October 2026. Implemented as schema version 4, which changes only the version record so that the mechanism exists before any data table needs it.
