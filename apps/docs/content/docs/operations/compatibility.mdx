## Supported configurations

| Component   | Supported        | Verified in CI                                                         |
| ----------- | ---------------- | ---------------------------------------------------------------------- |
| Node.js     | 24 or later      | Node.js 24, ESM and CommonJS consumers                                 |
| TypeScript  | 5.9.3 or later   | 5.9.3 and 7.0, with NodeNext and Bundler resolution                    |
| PostgreSQL  | 16 and 17        | Full integration suite on both                                         |
| Better Auth | `>=1.7.7 <1.8.0` | 1.7.7 across the [adapter matrix](/docs/better-auth/database-adapters) |

Standalone consumers are checked with `strict: true` and `skipLibCheck: false`. Better Auth consumers use `skipLibCheck` for upstream declarations while keeping application-level inference checks. Other JavaScript runtimes are not verified.

## Alpha policy

- Pin the exact version and commit your lockfile.
- Any alpha may change the public API, behavior, or storage. Each release's notes say what changed and how to migrate.
- Only the latest alpha receives fixes.
- Test producers, workers, and receivers together before rolling out.

## Package versions and schema versions

They are independent. Installing a package never runs SQL. The current delivery schema version is `3`, and `check()` refuses to start against any other. A future schema change ships its own upgrade SQL and a rollout order; do not assume old and new workers can share a changed schema or that downgrading is safe.

## What stays constant

Delivery is at least once with no ordering guarantee. Signing follows Standard Webhooks. Receivers keep verifying and deduplicating across upgrades. Store signing and encryption keys outside the deployment and retain whatever existing endpoints need.
