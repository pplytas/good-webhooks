description: Good Webhooks is a TypeScript library for outbound webhooks that lives in your application and your PostgreSQL database.
---

Good Webhooks gives your application three things that usually get rebuilt from scratch:

- **Endpoint management.** Your users register destinations, choose event types, pause, resume, and rotate secrets. Through a [Better Auth plugin](/docs/better-auth) or a standalone PostgreSQL provider.
- **Publication.** You publish typed events. Payloads are validated, idempotency keys are honored, and publication can run inside your own database transaction.
- **Delivery.** A worker you start sends signed [Standard Webhooks](https://www.standardwebhooks.com) requests, retries transient failures, records every attempt, and replays on demand.

Receivers verify requests with one function from `good-webhooks/verify`, or with any Standard Webhooks library.

```ts title="app.ts"
import { createWebhooks } from 'good-webhooks'
import { z } from 'zod'

const webhooks = createWebhooks({
  database: pool,
  encryptionKey: process.env.WEBHOOK_ENCRYPTION_KEY!,
  events: {
    'invoice.paid': z.object({ invoiceId: z.string(), amount: z.number().int() }),
  },
})

await webhooks.publish({
  type: 'invoice.paid',
  data: { invoiceId: 'inv_123', amount: 4200 },
  idempotencyKey: 'invoice.paid:inv_123',
})
```

## Why not build it yourself?

Most teams start with a `fetch()` in a request handler. The problems show up later: a customer's endpoint goes down and events are lost, a deploy sends duplicates, a secret leaks into logs, a rotated secret breaks a customer overnight, or a URL points at an internal service.

Good Webhooks handles the parts that are easy to get wrong and leaves the parts that belong to you:

| Good Webhooks owns                                       | Your application owns                              |
| -------------------------------------------------------- | -------------------------------------------------- |
| Endpoint lifecycle, encrypted secrets, URL safety checks | Who is allowed to manage which endpoints           |
| Payload validation, idempotency, recipient selection     | When to publish and in which transaction           |
| Signing, retries, attempt history, replay                | Starting and supervising the worker process        |
| Migration SQL and schema checks                          | Running migrations and owning database connections |
| Signature verification and payload parsing on receivers  | Deduplication and business processing              |

Nothing runs implicitly. Constructors open no connections, apply no migrations, and start no workers.

## Pick your setup

Management and delivery are independent. Combine them however your stack needs.

| You want                                                | Start here                                                |
| ------------------------------------------------------- | --------------------------------------------------------- |
| Everything on PostgreSQL, no auth framework             | [Quick start](/docs/quick-start)                          |
| Signed-in users managing their own endpoints            | [Better Auth plugin](/docs/better-auth)                   |
| Better Auth for management, Good Webhooks for delivery  | [Add delivery to Better Auth](/docs/better-auth/delivery) |
| Either management provider feeding your existing sender | [Custom senders](/docs/guides/custom-senders)             |

## Requirements

- Node.js 24 or later. The package ships ESM and also loads through CommonJS `require()`.
- PostgreSQL 16 or 17 for delivery or standalone management.
- Better Auth `>=1.7.7 <1.8.0` if you use the plugin. It is an optional peer dependency.
- TypeScript 5.9.3 or later for typed consumers.

Edge runtimes are not supported. The package targets Node.js.
