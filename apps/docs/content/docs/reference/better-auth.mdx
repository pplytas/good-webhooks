title: Better Auth

`good-webhooks/better-auth` adds authenticated endpoint management routes to Better Auth and exposes the same storage as a trusted provider. `good-webhooks/better-auth/client` is the matching [client plugin](#client-plugin).

```ts
import { goodWebhooks, createBetterAuthManagement } from 'good-webhooks/better-auth'
import type {
  GoodWebhooksOptions,
  WebhookEndpointDTO,
  ManagementAction,
  ScopeAuthorization,
  ScopePolicy,
} from 'good-webhooks/better-auth'
```

The optional peer range is `>=1.7.7 <1.8.0 || >=1.8.0-beta.0 <1.9.0-0`, tested on 1.7.7 and the newest 1.7 and 1.8 releases with these [databases](/docs/better-auth#supported-databases). For setup steps, see the [plugin guide](/docs/better-auth).

## goodWebhooks

```ts
goodWebhooks<const EventTypes extends readonly string[]>(
	options: GoodWebhooksOptions<EventTypes>,
)
```

```ts title="auth.ts"
import { betterAuth } from 'better-auth'
import { goodWebhooks } from 'good-webhooks/better-auth'
import { database } from './database.js' // Your existing database or adapter.

export const auth = betterAuth({
  database,
  secret: process.env.BETTER_AUTH_SECRET!,
  plugins: [goodWebhooks({ eventTypes: ['invoice.created', 'invoice.paid'] as const })],
})
```

Returns the `good-webhooks` Better Auth server plugin. It adds one management model and eight authenticated POST routes. It does not publish events, create delivery storage, or start a worker.

| Option             | Contract                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| `eventTypes`       | Required configured event names. A literal tuple preserves names in server and client types.            |
| `allowLocalhost`   | Optional boolean, default `false`. Permits development HTTP loopback destinations.                      |
| `schema.modelName` | Optional physical model name, default `webhookEndpoint`. This is not a PostgreSQL namespace.            |
| `schema.fields`    | Optional mapping from logical fields to physical field names.                                           |
| `authorizeScope`   | Optional policy required for application and custom scopes. Cannot override user or organization rules. |

### Storage model

Schema field names are `scopeKey`, `allocationKey`, `creationToken`, `url`, `description`, `eventTypes`, `additionalEventTypes`, `status`, `encryptedSecret`, `previousEncryptedSecret`, `previousSecretExpiresAt`, `revision`, `createdAt`, and `updatedAt`.

The plugin declares a unique `allocationKey` index for the per-scope endpoint limit. Generated fields and indexes are part of the storage contract. The host runs Better Auth's migration or schema-generation workflow. Standalone `management.sql` does not create this model.

Signing secrets are encrypted with the auth instance's secret configuration. Unlike the [PostgreSQL provider](/docs/reference/postgres#destination-checks), this provider does not resolve hostnames at registration. The worker still checks each destination before connecting.

## Authenticated routes

```ts
import { auth } from './auth.js'

export async function createEndpoint(request: Request) {
  return auth.api.createWebhookEndpoint({
    headers: request.headers,
    body: { url: 'https://receiver.example/webhooks', eventTypes: ['invoice.paid'] },
  })
}
```

Each route lives under Better Auth's configured base path. Every route uses sensitive session middleware and disables response storage. Server calls use `auth.api.<method>({ body, headers })` with the caller's session headers. Browsers use the [client plugin](#client-plugin).

| Server method                 | POST path                      | Body besides `scope?`                       | Result                 | Action   |
| ----------------------------- | ------------------------------ | ------------------------------------------- | ---------------------- | -------- |
| `createWebhookEndpoint`       | `/good-webhooks/create`        | `url`, `eventTypes`, `description?`         | `{ endpoint, secret }` | `create` |
| `listWebhookEndpoints`        | `/good-webhooks/list`          | None                                        | `WebhookEndpointDTO[]` | `read`   |
| `getWebhookEndpoint`          | `/good-webhooks/get`           | `id`                                        | `WebhookEndpointDTO`   | `read`   |
| `updateWebhookEndpoint`       | `/good-webhooks/update`        | `id`, `url?`, `description?`, `eventTypes?` | `WebhookEndpointDTO`   | `update` |
| `pauseWebhookEndpoint`        | `/good-webhooks/pause`         | `id`                                        | `WebhookEndpointDTO`   | `update` |
| `resumeWebhookEndpoint`       | `/good-webhooks/resume`        | `id`                                        | `WebhookEndpointDTO`   | `update` |
| `removeWebhookEndpoint`       | `/good-webhooks/remove`        | `id`                                        | `WebhookEndpointDTO`   | `delete` |
| `rotateWebhookEndpointSecret` | `/good-webhooks/rotate-secret` | `id`, `graceMs?`                            | `{ endpoint, secret }` | `update` |

`scope` accepts `{ type, id }`, `null`, or omission. Bodies reject unknown fields. Creation and updates use the [management input limits](/docs/reference/management#inputs-and-limits). An update accepts `description: null` to clear the value. Rotation accepts an integer `graceMs` from 0 through 86,400,000, defaulting to 86,400,000.

`WebhookEndpointDTO<EventType>` contains `id`, `url`, nullable `description`, `eventTypes`, `status`, `createdAt`, and `updatedAt`. Its timestamps are ISO strings, unlike trusted provider results, which contain `Date` values. Ordinary route results contain no signing material. Creation and rotation return the new secret separately.

## Scope authorization

Every route resolves an omitted scope to `{ type: 'user', id: session.user.id }`, then authorizes the requested scope and action as the [permissions guide](/docs/better-auth/permissions) describes. Application scope (`null`) and custom scope types need `authorizeScope`.

```ts
type ManagementAction = 'create' | 'read' | 'update' | 'delete'

interface ScopeAuthorization {
  scope: ManagementScope
  action: ManagementAction
  user: User
  session: Session
}

type ScopePolicy = (input: ScopeAuthorization) => boolean | Promise<boolean>
```

```ts
import { goodWebhooks, type ScopePolicy } from 'good-webhooks/better-auth'

const authorizeScope: ScopePolicy = ({ scope, action, user }) =>
  scope === null && action === 'read' && user.emailVerified

export const plugin = goodWebhooks({ eventTypes: ['invoice.paid'] as const, authorizeScope })
```

The policy defaults to denial and never overrides user or organization authorization. API keys do not authenticate these routes.

## Route errors

| Condition                       | HTTP status                                         |
| ------------------------------- | --------------------------------------------------- |
| Missing session                 | `401`                                               |
| Unauthorized scope or action    | `403`                                               |
| `INVALID_INPUT` or `UNSAFE_URL` | `400`                                               |
| `NOT_FOUND`                     | `404`                                               |
| `INVALID_STATE`                 | `409`                                               |
| Other `WebhookError`            | `500` with the message `Webhook management failed.` |

Better Auth validates request bodies and handles errors outside this mapping. The Good Webhooks error code remains in mapped error bodies.

## createBetterAuthManagement

```ts
createBetterAuthManagement(auth: { $context: Promise<object> }): Promise<EndpointManagement>
```

```ts
import { createBetterAuthManagement } from 'good-webhooks/better-auth'
import { auth } from './auth.js'

const management = await createBetterAuthManagement(auth)
await management.removeScope({ type: 'organization', id: 'org_123' })
```

Returns the same trusted management provider installed by `goodWebhooks`. A missing plugin produces `INVALID_CONFIG`.

This helper needs neither a session nor an HTTP listener. Direct calls bypass route authorization. It uses Better Auth's adapter and encryption helpers with the auth instance's secret configuration. App and worker must share compatible configuration, storage, and decryption keys. See [add delivery to Better Auth](/docs/better-auth/delivery).

The provider exposes every [EndpointManagement operation](/docs/reference/management#endpointmanagement), including `removeScope` and `reencrypt`, plus `source` for a sender. There are no HTTP routes for `removeScope` or `reencrypt`.

## Client plugin

The client plugin gives a Better Auth client typed methods for the plugin's routes.

```ts
goodWebhooksClient<const EventTypes extends readonly string[] = readonly string[]>(
	options?: { eventTypes: EventTypes },
)
```

```ts title="auth-client.ts"
import { createAuthClient } from 'better-auth/client'
import { goodWebhooksClient } from 'good-webhooks/better-auth/client'

const eventTypes = ['invoice.created', 'invoice.paid'] as const

export const authClient = createAuthClient({
  plugins: [goodWebhooksClient({ eventTypes })],
})
```

Returns a Better Auth client plugin for `createAuthClient`.

| Option       | Contract                                                                                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eventTypes` | Optional tuple that carries the server's event-name literals into client types. Omitting it leaves event names typed as `string`. It does not change the server's configured names or authorize requests. |

The dedicated client entry point has no runtime import of the server plugin, database driver, or delivery worker. It configures all Good Webhooks route methods as POST and preserves JSON values with `JSON.parse`, including descriptions that look like dates.

### Client methods

```ts
import { authClient } from './auth-client.js'

const { data, error } = await authClient.goodWebhooks.create({
  url: 'https://receiver.example/webhooks',
  eventTypes: ['invoice.paid'],
})
if (error) throw new Error(error.message)
console.log(data.secret) // Show once. No later response contains it.
```

All methods return Better Auth's client result containing `data` and `error`. Request bodies and data shapes match the [server routes](#authenticated-routes).

| Client method                                 | Server method                 | `data`                 |
| --------------------------------------------- | ----------------------------- | ---------------------- |
| `authClient.goodWebhooks.create(input)`       | `createWebhookEndpoint`       | `{ endpoint, secret }` |
| `authClient.goodWebhooks.list(input)`         | `listWebhookEndpoints`        | `WebhookEndpointDTO[]` |
| `authClient.goodWebhooks.get(input)`          | `getWebhookEndpoint`          | `WebhookEndpointDTO`   |
| `authClient.goodWebhooks.update(input)`       | `updateWebhookEndpoint`       | `WebhookEndpointDTO`   |
| `authClient.goodWebhooks.pause(input)`        | `pauseWebhookEndpoint`        | `WebhookEndpointDTO`   |
| `authClient.goodWebhooks.resume(input)`       | `resumeWebhookEndpoint`       | `WebhookEndpointDTO`   |
| `authClient.goodWebhooks.remove(input)`       | `removeWebhookEndpoint`       | `WebhookEndpointDTO`   |
| `authClient.goodWebhooks.rotateSecret(input)` | `rotateWebhookEndpointSecret` | `{ endpoint, secret }` |

Each input accepts optional `scope`. Omission selects the signed-in user's personal scope. `scope: null` requests application scope and requires server policy. The client does not weaken server authorization. See [scope authorization](#scope-authorization).

Endpoint timestamps remain ISO strings.
