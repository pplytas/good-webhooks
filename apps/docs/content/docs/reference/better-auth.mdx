The documented and tested baseline is Better Auth `1.7.7` on Node.js 24. The optional peer range is `>=1.7.7 <1.8.0`. Database support depends on the host adapter and its migration workflow. The [adapter compatibility page](/better-auth/database-adapters) lists tested combinations and limits.

## goodWebhooks

```ts
goodWebhooks<const EventTypes extends readonly string[]>(
	options: GoodWebhooksOptions<EventTypes>,
)
```

Returns the `good-webhooks` Better Auth server plugin. It adds one management model and eight authenticated POST routes. It does not publish events, create delivery storage, or start a worker.

| Option             | Contract                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| `eventTypes`       | Required configured event names. A literal tuple preserves names in server and client types.            |
| `allowLocalhost`   | Optional boolean, default `false`. Permits development HTTP loopback destinations.                      |
| `schema.modelName` | Optional physical model name, default `webhookEndpoint`. This is not a PostgreSQL namespace.            |
| `schema.fields`    | Optional mapping from logical fields to physical field names.                                           |
| `authorizeScope`   | Optional policy required for application and custom scopes. Cannot override user or organization rules. |

Schema field names are `scopeKey`, `allocationKey`, `creationToken`, `url`, `description`, `eventTypes`, `additionalEventTypes`, `status`, `encryptedSecret`, `previousEncryptedSecret`, `previousSecretExpiresAt`, `revision`, `createdAt`, and `updatedAt`.

The plugin declares a unique `allocationKey` index for the per-scope endpoint limit. Generated fields and indexes are part of the storage contract. The host runs Better Auth's migration or schema-generation workflow. Standalone `management.sql` does not create this model.

## Authenticated routes

Each route lives under Better Auth's configured base path. Every route uses sensitive session middleware and disables response storage. Server calls use `auth.api.<method>({ body, headers })` with the caller's session headers.

| Server method                 | POST path                      | Body besides `scope?`                       | Result                 | Action   |
| ----------------------------- | ------------------------------ | ------------------------------------------- | ---------------------- | -------- |
| `createWebhookEndpoint`       | `/good-webhooks/create`        | `url`, `eventTypes`, `description?`         | `{ endpoint, secret }` | `create` |
| `listWebhookEndpoints`        | `/good-webhooks/list`          | None                                        | `WebhookEndpointDTO[]` | `read`   |
| `getWebhookEndpoint`          | `/good-webhooks/get`           | `id`                                        | `WebhookEndpointDTO`   | `read`   |
| `updateWebhookEndpoint`       | `/good-webhooks/update`        | `id`, `url?`, `description?`, `eventTypes?` | `WebhookEndpointDTO`   | `update` |
| `pauseWebhookEndpoint`        | `/good-webhooks/pause`         | `id`                                        | `WebhookEndpointDTO`   | `update` |
| `resumeWebhookEndpoint`       | `/good-webhooks/resume`        | `id`                                        | `WebhookEndpointDTO`   | `update` |
| `removeWebhookEndpoint`       | `/good-webhooks/remove`        | `id`                                        | `WebhookEndpointDTO`   | `delete` |
| `rotateWebhookEndpointSecret` | `/good-webhooks/rotate-secret` | `id`, `graceMs?`                            | `{ endpoint, secret }` | `update` |

`scope` accepts `{ type, id }`, `null`, or omission. Bodies reject unknown fields. Creation and updates use the [management input limits](/reference/management). An update accepts `description: null` to clear the value. Rotation accepts an integer `graceMs` from 0 through 86,400,000, defaulting to 86,400,000.

`WebhookEndpointDTO<EventType>` contains `id`, `url`, nullable `description`, `eventTypes`, `status`, `createdAt`, and `updatedAt`. Its timestamps are ISO strings, unlike trusted provider results, which contain `Date` values. Ordinary route results contain no signing material. Creation and rotation return the new secret separately.

## Scope authorization

| Requested scope | Authorization                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------- |
| Omitted         | Resolves to `{ type: 'user', id: session.user.id }`.                                              |
| `user`          | The ID must exactly match the current user.                                                       |
| `organization`  | Requires the organization plugin, current membership, and the requested `webhookEndpoint` action. |
| `null`          | Application scope. Requires `authorizeScope` to allow the exact action.                           |
| Another type    | Requires `authorizeScope` to allow that scope and action.                                         |

The organization plugin's configured creator role has full endpoint access. Other roles need explicit grants. A role named `admin` does not receive grants by name alone. Organization-owned API keys are not an authentication path for these routes. User API-key session impersonation is not a promised compatibility path in this version.

```ts
type ManagementAction = 'create' | 'read' | 'update' | 'delete'

interface ScopeAuthorization {
  scope: ManagementScope
  action: ManagementAction
  user: User
  session: Session
}

type ScopePolicy = (input: ScopeAuthorization) => boolean | Promise<boolean>
```

The policy defaults to denial for application and custom scopes. It does not run as an override for user or organization authorization.

Deleting a user retires their personal endpoints. Deleting an organization through the organization endpoint retires its endpoints. Trusted sender lookups also check owner existence. Removing a member revokes that member's management access without retiring the organization's endpoints.

## Route errors

| Condition                       | HTTP status                                         |
| ------------------------------- | --------------------------------------------------- |
| Missing session                 | `401`                                               |
| Unauthorized scope or action    | `403`                                               |
| `INVALID_INPUT` or `UNSAFE_URL` | `400`                                               |
| `NOT_FOUND`                     | `404`                                               |
| `INVALID_STATE`                 | `409`                                               |
| Other `WebhookError`            | `500` with the message `Webhook management failed.` |

Better Auth validates request bodies and handles errors outside this mapping. The Good Webhooks error code remains in mapped error bodies.

## createBetterAuthManagement

```ts
createBetterAuthManagement(auth: { $context: Promise<object> }): Promise<EndpointManagement>
```

Returns the same trusted management provider installed by `goodWebhooks`. A missing plugin produces `INVALID_CONFIG`.

This helper needs neither a session nor an HTTP listener. Direct calls bypass route authorization. It uses Better Auth's adapter and encryption helpers with the auth instance's secret configuration. App and worker must share compatible configuration, storage, and decryption keys.

The provider exposes every [EndpointManagement operation](/reference/management), including `removeScope` and `reencrypt`, plus `source` for a sender. There are no HTTP routes for `removeScope` or `reencrypt`.
