## getPostgresMigration

```ts
getPostgresMigration(options?: PostgresMigrationOptions): string
```

Returns fresh-install SQL. It never connects to a database or applies DDL. The host applies the SQL once in a transaction and records it in its migration ledger.

<auto-type-table path="../../reference-types.ts" name="PostgresMigrationOptions" />

| Option      | Default    | Meaning                                        |
| ----------- | ---------- | ---------------------------------------------- |
| `schema`    | `'public'` | Namespace for all tables emitted by this call. |
| `component` | `'all'`    | `'management'`, `'delivery'`, or `'all'`.      |

Every generated script starts with `CREATE SCHEMA IF NOT EXISTS` for its target namespace. Table creation is not idempotent. Reapplying initial SQL is not an upgrade procedure.

## Components and SQL assets

| Component    | Created tables                                                                                                 | Equivalent shipped asset for `public`      |
| ------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `management` | `webhook_endpoints`                                                                                            | `good-webhooks/migrations/management.sql`  |
| `delivery`   | `webhook_schema_version`, `webhook_endpoint_state`, `webhook_events`, `webhook_deliveries`, `webhook_attempts` | `good-webhooks/migrations/delivery.sql`    |
| `all`        | Both groups                                                                                                    | `good-webhooks/migrations/001-initial.sql` |

All three `.sql` files are public package exports. They can be resolved through `import.meta.resolve` or `require.resolve` and read by a host migration tool. They are text assets, not executable JavaScript imports.

The current delivery schema version is `3`. `createDelivery().check()` expects exactly that version. Earlier prototype storage needs an explicit upgrade plan or fresh storage. None of these assets upgrades existing data.

## Schema names

A schema must be a nonblank, well-formed string of at most 63 UTF-8 bytes without null bytes. The generator and runtime quote names as PostgreSQL identifiers. Invalid names or components produce `INVALID_CONFIG`.

The `schema` passed to a runtime must match the corresponding migration. Management and delivery can use separate namespaces by generating each component separately. An injected management provider keeps its own configured namespace regardless of delivery options.

Better Auth management follows its adapter's schema workflow. These migrations cover the standalone PostgreSQL provider and delivery only. `goodWebhooks({ schema: { modelName, fields } })` changes model and field names, not PostgreSQL placement.
