## EndpointManagement

All direct calls are trusted server operations. The first argument is `ManagementScope`, either `null` for application scope or `{ type, id }` for a named scope. `type` accepts 1 through 64 characters and `id` accepts 1 through 200. Both must be nonblank and contain no null bytes.

| Method                              | Result and behavior                                                                                                                          |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `create(scope, input)`              | `Promise<ManagedEndpointWithSecret>`. Creates an active endpoint and returns `{ endpoint, secret }`.                                         |
| `list(scope)`                       | `Promise<ManagedEndpoint[]>`. Returns every nondeleted endpoint in the scope.                                                                |
| `get(scope, id)`                    | `Promise<ManagedEndpoint>`. Returns an endpoint, including its deleted state.                                                                |
| `update(scope, id, patch)`          | `Promise<ManagedEndpoint>`. Changes the supplied mutable fields.                                                                             |
| `pause(scope, id)`                  | `Promise<ManagedEndpoint>`. Changes the status to `'paused'`.                                                                                |
| `resume(scope, id)`                 | `Promise<ManagedEndpoint>`. Validates the current URL and changes status to `'active'`.                                                      |
| `remove(scope, id)`                 | `Promise<ManagedEndpoint>`. Sets status to `'deleted'` and clears signing secrets. Removing an already deleted record is idempotent.         |
| `rotateSecret(scope, id, options?)` | `Promise<ManagedEndpointWithSecret>`. Changes the signing secret. `options.graceMs` defaults to 86,400,000 and accepts 0 through 86,400,000. |
| `removeScope(scope)`                | `Promise<void>`. Deletes the scope's currently registered endpoints.                                                                         |
| `reencrypt(scope)`                  | `Promise<number>`. Rewrites live signing-secret ciphertext using the current storage key and returns the count.                              |
| `source`                            | Trusted sender reads described below.                                                                                                        |

`CreateManagedEndpoint` has `url`, optional `description`, and `eventTypes`. `UpdateManagedEndpoint` makes those fields optional and accepts `null` to clear the description. Each scope permits at most 1,000 nondeleted endpoints. An endpoint subscribes to 1 through 100 configured event names. Duplicate subscriptions are collapsed.

Endpoint IDs accepted by management contain 1 through 255 characters, must be nonblank, and cannot contain null bytes. Descriptions accept at most 2,000 characters without null bytes. URLs accept at most 2,048 characters and must pass the configured destination validation.

`ManagedEndpoint` is the shared `Endpoint` shape: `id`, `url`, nullable `description`, `eventTypes`, `status`, `createdAt`, and `updatedAt`. Timestamps are `Date` values. Ordinary results contain neither plaintext signing secrets nor ciphertext.

Deleted endpoints cannot be updated, paused, resumed, or rotated. A second rotation during an active overlap fails unless `graceMs: 0` explicitly replaces all current signing material. Re-encryption preserves signing values and includes paused endpoints.

Expected errors include `INVALID_INPUT`, `UNSAFE_URL`, `NOT_FOUND`, and `INVALID_STATE`. Conflicting updates retry with revision checks and eventually produce `INVALID_STATE` if the record keeps changing.

## EndpointSource

```ts
interface EndpointSource {
  matchRecipients(scope: ManagementScope, eventType: string): Promise<readonly string[]>
  resolveEndpoint(scope: ManagementScope, id: string): Promise<EndpointResolution>
}

type EndpointResolution =
  { status: 'active'; url: string; secrets: readonly string[] } | { status: 'paused' | 'deleted' }
```

`matchRecipients` returns the complete matching set, including paused endpoints. Lookup failures reject. A source must not convert an outage into an empty result. Concurrent edits can produce a result that reflects different moments; the contract does not promise a scope-wide snapshot.

`resolveEndpoint` returns current state before an attempt. Active results contain the current URL and usable Standard Webhooks signing secrets. Deleted or missing records return `'deleted'`. A missing Better Auth user or organization also makes its endpoints ineligible. Lookup and decryption failures reject.

The built-in management source returns the new signing secret first and the previous secret only while the overlap remains active. The source is not an API for untrusted callers. Custom senders also own [recipient persistence and safe transport](/docs/guides/custom-senders).

## createManagement

```ts
createManagement(options: ManagementOptions): EndpointManagement
```

Creates shared lifecycle behavior over custom persistence and encryption.

| Option               | Contract                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `repository`         | Required `ManagementRepository`.                                                                                     |
| `cipher`             | Required `SecretCipher`.                                                                                             |
| `eventTypes`         | Required nonempty array of names matching `^[a-zA-Z0-9][a-zA-Z0-9_.:-]{0,119}$`. No payload validators are required. |
| `allowLocalhost`     | Optional boolean, default `false`. Allows development HTTP loopback URLs.                                            |
| `validateUrl(url)`   | Optional async host check after portable URL validation.                                                             |
| `scopeExists(scope)` | Optional async ownership check. Returns `false` for a missing owner and rejects on lookup failure.                   |

With `scopeExists`, ordinary reads and writes reject missing owners with `NOT_FOUND`. `remove` and `removeScope` skip that check so an owner can still be cleaned up after deletion. Sender matching returns no recipients for a missing owner, and resolution returns `'deleted'`. Creation also checks ownership after the insert so a concurrent owner deletion cannot leave a live orphan.

## ManagementRepository

```ts
interface ManagementRepository {
  list(scope: ManagementScope): Promise<StoredEndpoint[]>
  get(scope: ManagementScope, id: string): Promise<StoredEndpoint | null>
  create(scope: ManagementScope, endpoint: Omit<StoredEndpoint, 'id'>): Promise<StoredEndpoint>
  update(
    scope: ManagementScope,
    id: string,
    revision: number,
    patch: StoredEndpointPatch,
  ): Promise<StoredEndpoint | null>
}
```

`list` returns every live record without truncation. `create` atomically enforces the strict 1,000-record scope limit. `update` atomically guards on scope, ID, and revision, increments the revision, and applies the patch. A revision conflict returns `null`. Repository errors propagate.

`StoredEndpoint` adds `revision`, `encryptedSecret`, nullable `previousEncryptedSecret`, and nullable `previousSecretExpiresAt` to the endpoint shape. `StoredEndpointPatch` is a partial stored record without `id`, `createdAt`, or `revision`. Stored records must never be sent to clients.

## SecretCipher

```ts
interface SecretCipher {
  encrypt(value: string): Promise<string>
  decrypt(value: string): Promise<string>
}
```

The cipher encrypts receiver-facing signing secrets. A cipher that supports storage-key rotation writes with the current key and reads the retained keys until re-encryption finishes.

This entrypoint exports every contract named on this page, plus the aliases `ManagedEndpoint`, `CreateManagedEndpoint`, `UpdateManagedEndpoint`, and `ManagedEndpointWithSecret`.
