Each process imports only the entry point it needs. A receiver never loads database code, and only the two `better-auth` entry points import Better Auth, an optional peer.

| Import                                                                          | Use it for                                                           |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| [`good-webhooks`](/docs/reference/core)                                         | `createWebhooks()`: management and delivery together on PostgreSQL   |
| [`good-webhooks/delivery`](/docs/reference/delivery)                            | `createDelivery()`: the sender alone, fed by any `EndpointSource`    |
| [`good-webhooks/management`](/docs/reference/management)                        | The management contracts and `createManagement()` for custom storage |
| [`good-webhooks/management/postgres`](/docs/reference/postgres)                 | Standalone endpoint management without delivery tables               |
| [`good-webhooks/better-auth`](/docs/reference/better-auth)                      | The Better Auth server plugin and trusted management provider        |
| [`good-webhooks/better-auth/client`](/docs/reference/better-auth#client-plugin) | The Better Auth client plugin for browsers                           |
| [`good-webhooks/verify`](/docs/reference/verify)                                | `parseWebhook()` and `verifyWebhook()` for receivers                 |
| [`good-webhooks/migrations`](/docs/reference/migrations)                        | `getPostgresMigration()`, `getPostgresUpgrade()`, and the SQL files  |

Every expected failure is a [`WebhookError`](/docs/reference/errors) with a stable `code`.

## Conventions

- Constructors validate options and return. They never open connections, apply migrations, or start workers.
- Database and provider failures can propagate as other error types.
- Trusted provider results use `Date` values. Better Auth route responses use ISO strings.
- Scope arguments are `null` for application scope or `{ type, id }` for a named scope. Selecting a scope never authorizes the caller. See [scopes](/docs/concepts/scopes).
