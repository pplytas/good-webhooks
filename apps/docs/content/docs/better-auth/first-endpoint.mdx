title: Manage your first endpoint
description: Create and list an endpoint through an authenticated Better Auth session, using SQLite.
---

Create a Better Auth user, register a personal webhook endpoint, and list it through authenticated routes. This tutorial uses a persistent SQLite file. It does not send a webhook or require PostgreSQL.

Use Node.js 24 or later. First [build the local package archive](/getting-started/installation#create-an-archive).

## Create a tutorial application

Choose a new directory outside the repository:

```sh
mkdir good-webhooks-auth-tutorial
cd good-webhooks-auth-tutorial
npm init -y
npm install /absolute/path/to/good-webhooks/artifacts/good-webhooks-0.1.0-alpha.1.tgz better-auth@1.7.7
```

Generate a local auth secret once and keep this shell open:

```sh
export BETTER_AUTH_SECRET="$(node -e 'console.log(require("node:crypto").randomBytes(32).toString("base64"))')"
```

A deployed app stores this secret in its secret manager. Every app and worker that reads these endpoints needs compatible retained secrets.

## Create the runnable application

Save this file as `tutorial.mjs`. It applies the Better Auth schema explicitly before serving requests. The migration function is used here for a disposable native SQLite tutorial; an existing app should use its normal [schema workflow](/better-auth/configuration).

```js title="tutorial.mjs"
import assert from 'node:assert/strict'
import { randomUUID } from 'node:crypto'
import { DatabaseSync } from 'node:sqlite'
import { betterAuth } from 'better-auth'
import { getMigrations } from 'better-auth/db/migration'
import { goodWebhooks } from 'good-webhooks/better-auth'

const secret = process.env.BETTER_AUTH_SECRET
if (!secret) throw new Error('Set BETTER_AUTH_SECRET before running the tutorial.')

const database = new DatabaseSync('./tutorial.sqlite')
const origin = 'http://localhost:3000'
const options = {
  database,
  baseURL: origin,
  secret,
  emailAndPassword: { enabled: true },
  plugins: [goodWebhooks({ eventTypes: ['invoice.created', 'invoice.paid'] })],
}
let auth

async function call(operation, body = {}, sessionHeaders = new Headers()) {
  const headers = new Headers(sessionHeaders)
  headers.set('origin', origin)
  headers.set('content-type', 'application/json')
  return auth.handler(
    new Request(`${origin}/api/auth/good-webhooks/${operation}`, {
      method: 'POST',
      headers,
      body: JSON.stringify(body),
    }),
  )
}

let endpointId
let sessionHeaders
try {
  await (await getMigrations(options)).runMigrations()
  auth = betterAuth(options)
  const signup = await auth.api.signUpEmail({
    body: {
      name: 'Tutorial user',
      email: `tutorial-${randomUUID()}@example.com`,
      password: `tutorial-${randomUUID()}`,
    },
    asResponse: true,
  })
  assert.equal(signup.status, 200)
  sessionHeaders = new Headers({
    origin,
    cookie: signup.headers
      .getSetCookie()
      .map((value) => value.split(';')[0])
      .join('; '),
  })

  assert.equal((await call('list')).status, 401)
  console.log('Unauthenticated request rejected: 401')

  const response = await call(
    'create',
    {
      url: 'https://receiver.example/webhooks',
      eventTypes: ['invoice.created'],
    },
    sessionHeaders,
  )
  assert.equal(response.status, 200)
  const created = await response.json()
  endpointId = created.endpoint.id
  assert.match(created.secret, /^whsec_/)
  console.log('Created personal endpoint:', endpointId)
  // In your application, transfer created.secret securely to the receiver.

  const listing = await call('list', {}, sessionHeaders)
  assert.equal(listing.status, 200)
  const endpoints = await listing.json()
  assert.equal(endpoints.length, 1)
  assert.equal(endpoints[0].id, endpointId)
  assert.equal('secret' in endpoints[0], false)
  console.log('Listed one endpoint without exposing its signing secret.')

  const applicationScope = await call('list', { scope: null }, sessionHeaders)
  assert.equal(applicationScope.status, 403)
  console.log('Application scope rejected without an explicit policy: 403')
} finally {
  try {
    if (endpointId && sessionHeaders) {
      const removed = await call('remove', { id: endpointId }, sessionHeaders)
      assert.equal(removed.status, 200)
    }
  } finally {
    database.close()
  }
}
```

`auth.handler()` receives real `Request` objects in this local program. There is no network listener to start. The cookie from sign-up authenticates the endpoint calls.

## Run the tutorial

```sh
node tutorial.mjs
```

Expect a rejected unauthenticated request, a created endpoint ID, a list with one endpoint, and a rejected application-scope request. The endpoint is retired before exit. The user and management history remain in `tutorial.sqlite`.

On repeated runs, Better Auth 1.7.7's SQLite migration inspector can warn that `eventTypes` and `additionalEventTypes` expect `string[]` but use `TEXT` storage. The tutorial's create and list checks still pass. Do not delete an existing application's database to silence these warnings.

Omitting `scope` selects the authenticated user's personal endpoints. `scope: null` requests application scope, which needs an explicit authorization policy.

## Connect your application

Add the same server plugin to your existing auth instance. Mount its handler using your framework's Better Auth integration. Add the dedicated client plugin to call it from the browser:

```ts
import { createAuthClient } from 'better-auth/client'
import { goodWebhooksClient } from 'good-webhooks/better-auth/client'

const eventTypes = ['invoice.created', 'invoice.paid'] as const
export const authClient = createAuthClient({
  plugins: [goodWebhooksClient({ eventTypes })],
})

// Call after the user signs in to this application.
const result = await authClient.goodWebhooks.list({})
```

Keep the event-name tuple shared between server and client. Import only the client entrypoint in browser code.

After completing this disposable tutorial, you can delete `tutorial.sqlite`. Do not delete an application's existing auth database.
