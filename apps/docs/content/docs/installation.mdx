This page sets up the PostgreSQL setup in an existing app. Using Better Auth for endpoint management? Install here, then continue with the [Better Auth plugin](/docs/better-auth).

**Requirements:** Node.js 24 or later, PostgreSQL 16 or 17, and for TypeScript, version 5.9.3 or later with `moduleResolution` set to `NodeNext` or `Bundler`. Edge runtimes are not supported.

<Steps>
<Step>
### Install

<Tabs groupId="setup" persist items={['PostgreSQL', 'Better Auth', 'Receiver only']}>
<Tab>

```package-install
good-webhooks@alpha pg zod
```

```package-install
npm install --save-dev @types/pg
```

</Tab>
<Tab>

```package-install
good-webhooks@alpha better-auth@1.7.7
```

Add `pg zod` too if the same app will [send events](/docs/better-auth/delivery). Supported range: `better-auth >=1.7.7 <1.8.0`. Then follow the [Better Auth plugin](/docs/better-auth) guide; the steps below are for the PostgreSQL setup.

</Tab>
<Tab>

You only receive webhooks from a Good Webhooks sender:

```package-install
good-webhooks@alpha zod
```

Skip the steps below and go to [receive webhooks](/docs/guides/receive). `good-webhooks/verify` has no database dependency.

</Tab>
</Tabs>

The `alpha` tag installs the latest alpha. Commit your lockfile. Payload schemas can use any [Standard Schema](https://standardschema.dev) library; these docs use Zod.

</Step>
<Step>
### Create a storage key

Endpoint signing secrets are encrypted in your database with this key. Generate it once:

```sh
node -e 'import("good-webhooks").then(m => console.log(m.generateEncryptionKey()))'
```

Store the output in your secret manager or `.env` as `WEBHOOK_ENCRYPTION_KEY`. Every process that sends or manages webhooks needs the **same** key.

</Step>
<Step>
### Create the tables

Write the SQL to a migration file:

```sh
node -e 'import("good-webhooks/migrations").then(m => process.stdout.write(m.getPostgresMigration()))' > 001-webhooks.sql
```

Apply it with the migration tool you already use, or with `psql`:

```sh
psql "$DATABASE_URL" --single-transaction -v ON_ERROR_STOP=1 -f 001-webhooks.sql
```

The tables are prefixed `webhook_` and go in `public`. To use another schema, see [migrations](/docs/operations/migrations).

</Step>
<Step>
### Create the client

```ts title="webhooks.ts"
import { createWebhooks } from 'good-webhooks'
import { Pool } from 'pg'
import { z } from 'zod'

export const pool = new Pool({ connectionString: process.env.DATABASE_URL })

export const webhooks = createWebhooks({
  database: pool,
  encryptionKey: process.env.WEBHOOK_ENCRYPTION_KEY!,
  events: {
    'invoice.paid': z.object({ invoiceId: z.string(), amount: z.number().int() }),
  },
})
```

Check the setup once at startup. It throws `SCHEMA_MISMATCH` if the tables are missing or outdated:

```ts
await webhooks.check()
```

</Step>
</Steps>

You're set up. Nothing is sent yet: that takes a published event and a running worker.

## Entry points

Import only what a process needs. A receiver never loads database code.

| Import                              | Use it for                                                           |
| ----------------------------------- | -------------------------------------------------------------------- |
| `good-webhooks`                     | `createWebhooks()`: management and delivery together on PostgreSQL   |
| `good-webhooks/delivery`            | `createDelivery()`: the sender alone, fed by any `EndpointSource`    |
| `good-webhooks/management`          | The management contracts and `createManagement()` for custom storage |
| `good-webhooks/management/postgres` | Standalone endpoint management without delivery tables               |
| `good-webhooks/better-auth`         | The Better Auth server plugin and trusted management provider        |
| `good-webhooks/better-auth/client`  | The Better Auth client plugin for browsers                           |
| `good-webhooks/verify`              | `parseWebhook()` and `verifyWebhook()` for receivers                 |
| `good-webhooks/migrations`          | `getPostgresMigration()` and the shipped SQL files                   |

The package ships ESM and also loads through CommonJS `require()` on Node.js 24. If you use the Better Auth plugin, enable `skipLibCheck` for its upstream declarations; your own types stay fully checked.
