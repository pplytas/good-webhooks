title: Install Good Webhooks
description: Install the alpha package from npm and choose the dependencies for your setup.
---

Good Webhooks is in alpha and requires Node.js 24 or later.

## Install in your application

Run this command from your application's directory:

```sh
npm install good-webhooks@alpha
```

The `alpha` tag selects the current alpha release. To save its exact version in `package.json`, use `npm install --save-exact good-webhooks@alpha`. Commit your lockfile and review the [release notes](https://github.com/pplytas/good-webhooks/releases) before upgrading.

For standalone PostgreSQL management or built-in delivery, install the driver you use to supply a database connection. These guides use node-postgres and Zod for payload schemas:

```sh
npm install pg zod
npm install --save-dev @types/pg
```

For Better Auth management, use the tested Better Auth version:

```sh
npm install better-auth@1.7.7
```

Better Auth is an optional peer. The declared peer range is `>=1.7.7 <1.8.0`; the compatibility checks use 1.7.7. Standalone management, delivery, and verification do not require it.

The package ships ESM. Node.js 24 can load this build through either `import` or CommonJS `require()`. Applications can use npm, pnpm, or another compatible package manager.

TypeScript applications need TypeScript 5.9.3 or later. Consumer checks cover both NodeNext and Bundler resolution. Better Auth consumers should enable `skipLibCheck` for its upstream declarations; application-level event and payload checks still apply. See [compatibility and upgrades](/operations/compatibility).

## Choose a first tutorial

- [Manage your first endpoint with Better Auth](/better-auth/first-endpoint) uses a local SQLite file and an authenticated session. It needs no sender or PostgreSQL.
- [Send your first webhook](/getting-started/first-delivery) delivers a signed event through PostgreSQL and verifies it at a local receiver.

## Prepare the checkout

To try unreleased changes, build a local archive from the repository.

Use Node.js 24 or later and the pnpm version pinned in the root `package.json`. With Corepack installed, enable its pnpm shim once:

```sh
corepack enable pnpm
```

Corepack selects the repository pin when you run pnpm inside the checkout. If your Node installation has no Corepack, follow [pnpm installation](https://pnpm.io/installation) before continuing.

```sh
git clone https://github.com/pplytas/good-webhooks.git
cd good-webhooks
pnpm install --frozen-lockfile
pnpm --filter good-webhooks build
```

The library lives in `packages/good-webhooks`. The documentation app lives in `apps/docs`. Run contributor commands from the repository root unless a step says otherwise.

## Create an archive

```sh
mkdir -p artifacts
pnpm --dir packages/good-webhooks pack --pack-destination ../../artifacts
```

The archive is `artifacts/good-webhooks-0.1.0-alpha.2.tgz`. Packing runs the library build. It includes the compiled package and its SQL assets, without the documentation app.

## Install the local archive

Run this command from your application's directory. Replace the absolute path with your checkout's path.

```sh
npm install /absolute/path/to/good-webhooks/artifacts/good-webhooks-0.1.0-alpha.2.tgz
```
